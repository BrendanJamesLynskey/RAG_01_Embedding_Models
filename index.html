01

Why Embeddings — The Geometry of Meaning

An embedding is a real-valued vector that encodes the semantic position of a token sequence in a high-dimensional space. The key property is metric: similar meanings live close together under cosine similarity or dot product, enabling sub-linear nearest-neighbour search instead of full corpus comparison.

There are two competing traditions:

Sparse (lexical)

BM25, SPLADE, TF-IDF. The vector dimensionality equals the vocabulary size (≈30,000–250,000). Most entries are zero. Exact term match. Fast. Fragile to synonyms and paraphrases. SPLADE v2 learns importance weights per term via a BERT-like MLM head, recovering some semantic generalisation.

Dense (semantic)

BERT-derived encoders, collapsed to a single fixed-size vector (typically 256–4096 dims) via CLS-token or mean pooling. No term-overlap required. Captures paraphrases. Slower to build index, faster per-query via ANN. Sensitive to domain shift — the core challenge this deck addresses.

The unit of meaning

The pooling choice is load-bearing. CLS pooling works well when the encoder was pre-trained with a CLS objective (vanilla BERT). Mean pooling outperforms CLS on most retrieval benchmarks when the model is fine-tuned with a contrastive objective (sentence-transformers default since 2021). Weighted mean (by token importance) is used in some SPLADE-family hybrids.

Bi-Encoder vs Cross-Encoder

The most important architectural fork. Nearly every production RAG pipeline uses both: bi-encoder for retrieval, cross-encoder for reranking.

The asymmetric encoding trick

Many production bi-encoders use asymmetric encoding: query and document use different prompt prefixes (e.g. query: ... vs passage: ... for E5 models). This is not cosmetic — the encoder's representation space is shaped differently for short questions vs long passages. Forgetting the prefix prefix is one of the most common production bugs: NDCG@10 can drop 3–8 points silently.

BGE-M3 is trained with a hybrid objective that produces three retrieval modes from a single model: dense embedding, sparse (lexical weight) output, and ColBERT-style multi-vector output. The BGEM3FlagModel Python class exposes all three simultaneously; each adds latency but raises recall. For most English-only production use, dense-only BGE-M3 at 1024 dims is the default choice.

ColBERT & Late Interaction

ColBERT (Contextualised Late Interaction over BERT, Khattab & Zaharia 2020) occupies a middle ground: it is cheaper than a cross-encoder and more expressive than a bi-encoder. The insight is to defer the query–document interaction until after both sequences are encoded, but to keep per-token vectors rather than collapsing to a single pool.

The MaxSim operator: for each query token vector q𝑖, find the maximum dot-product over all document token vectors dⱼ. Sum the per-token maxima. This yields a score that respects the term-level alignment between query and document without requiring all tokens to interact in a single attention matrix.

ColBERT MaxSim in NumPy (simplified)
import numpy as np

def maxsim_score(Q: np.ndarray, D: np.ndarray) -> float:
    # Q: [n_q, 128]  D: [n_d, 128], both L2-normalised
    scores = Q @ D.T          # [n_q, n_d]
    return float(scores.max(axis=1).sum())

# Index storage: one 128-dim vector per token per document
# ColBERTv2 + PLAID compresses to ~4 bits/dim via residual quantisation
PLAID — ColBERTv2 at scale

PLAID (Performance-optimised Late Interaction Driver, Santhanam et al. 2022) makes ColBERT practical at >100 M documents. It uses residual vector quantisation (centroids + residuals, ≈4 bits/dim) and a two-stage candidate generation: (1) IVF over centroid cluster assignments to find candidate documents, (2) full MaxSim on GPU over the short-list. On MS MARCO, PLAID achieves MRR@10 of 39.7 with <100 ms end-to-end on a single A100. The RAGatouille library (pip install ragatouille) wraps ColBERTv2 + PLAID for production use.

05

Matryoshka Embeddings — One Model, Many Dimensions

Matryoshka Representation Learning (MRL, Kusupati et al. 2022) trains a single encoder such that any prefix of the output vector is itself a valid, useful embedding. You can truncate a 768-dim vector to 64 dims and still get reasonable retrieval, with quality scaling smoothly as you increase dimension.

Training objective

Standard contrastive loss is applied simultaneously at multiple granularities: full dimension D, D/2, D/4, … down to some minimum (e.g. 64). The loss is summed across all resolutions with equal or geometrically-decreasing weights. This forces the model to pack the most important dimensions first.

Production benefit

Deploy one model but run it at different precisions depending on latency budget. Index tier-1 docs at 1536 dims; tier-2 at 256 dims. OpenAI's text-embedding-3-large (3072 d) and text-embedding-3-small (1536 d) both use MRL — the API accepts a dimensions parameter to truncate server-side, saving egress bandwidth and index memory.

Domain Adaptation — TSDAE, GPL, Hard Negative Mining

Off-the-shelf models trained on MS MARCO or NLI datasets often degrade significantly on specialised domains (legal, biomedical, financial, customer support). Three techniques address this without requiring manual annotation at scale.

TSDAE

Transformation-based Sequential Denoising Auto-Encoder (Wang et al. 2021). Corrupt input sentences (delete 60% of tokens), encode, reconstruct from the CLS embedding. No labels needed — just raw domain text. 10–20k sentences, ~1 GPU-hour on A100. BEIR domain-transfer gains: +2–5 NDCG@10 on out-of-domain tasks compared to fine-tuning with weak signals.

GPL

Generative Pseudo Labelling (Wang et al. 2021). Use T5-based query generation (BeIR/query-gen-msmarco-t5-base-v1) to synthesise queries for each domain passage. A cross-encoder scores the synthetic (query, passage) pair. The score becomes the label for margin-MSE training on the bi-encoder. GPL closes 70–80% of the gap between zero-shot and supervised fine-tuning with human labels.

Hard Negative Mining

The most impactful signal. Mine false-positive documents that score high under BM25 or the current bi-encoder but are semantically wrong (e.g. same keyword, different meaning). Training with hard negatives prevents the model from relying on lexical overlap. AugSBERT uses cross-encoder scores to identify hard negatives. Library: sentence-transformers >= 2.2 has MultipleNegativesRankingLoss with mine support.

GPL fine-tuning pipeline sketch (sentence-transformers)
from sentence_transformers import SentenceTransformer, losses
from sentence_transformers.datasets import NoDuplicatesDataLoader

model = SentenceTransformer("BAAI/bge-base-en-v1.5")

# GPL-generated triplets: (query, positive_passage, negative_passage)
train_loss = losses.MultipleNegativesRankingLoss(model)

# warm-up 10 % of steps, then cosine LR decay
model.fit(
    train_objectives=[(dataloader, train_loss)],
    epochs=1,
    warmup_steps=100,
    output_path="./domain-adapted-bge",
)

Evaluating Embeddings — MTEB, BEIR, In-Domain Evals

Never trust a model ranking from a provider's blog post. Understand what each benchmark measures before picking a model for production.

MTEB is necessary but not sufficient

A model that ranks #1 on MTEB Retrieval English may be mediocre on your internal helpdesk corpus because MTEB's retrieval tasks are predominantly Wikipedia-style questions. Always measure in-domain Recall@100 (the input to your reranker) before committing to a model. The fastest way: embed 500–1000 manually labelled QA pairs from your domain and compute recall across candidate models in an afternoon.

Practical Sizing — Dim, Throughput, GPU vs CPU

Embedding infrastructure is often the largest ongoing compute cost in a RAG system. The decisions compound: higher dimension → larger index → slower ANN → more RAM → higher hosting cost.

int8 quantisation — the free lunch

INT8 quantisation of the encoder (via optimum + ONNX Runtime) typically halves memory and increases throughput 1.5–2× with < 0.5% NDCG@10 regression on BEIR for models ≥ 100 M params. The sentence-transformers SentenceTransformer constructor now accepts model_kwargs={"torch_dtype": torch.float16} for fp16 deployment. Never store vectors in float64 — float32 is the standard index precision; float16 is acceptable for cosine similarity with modern FAISS builds.

09

What to Take Away

  • Dense beats sparse for paraphrase retrieval; sparse beats dense for exact-term recall. Hybrid is almost always better than either alone.
  • Bi-encoder for retrieval, cross-encoder for reranking. Never use a cross-encoder at index time; never use a bi-encoder as the final ranker if quality matters.
  • BGE-M3 is the strongest open-weights general-purpose choice as of 2025-Q1. It supports dense, sparse, and ColBERT modes from a single model.
  • ColBERT + PLAID is the right architecture when you want cross-encoder quality at bi-encoder latency and can afford 4–8× the storage.
  • Matryoshka (MRL) lets you trade quality for speed at deployment time without retraining. OpenAI text-embedding-3 and nomic-embed-text-v1.5 both support it.
  • Domain-adapt before you scale. GPL on 10 k domain sentences will outperform the best off-the-shelf model on your corpus if your domain is specialised.
  • Measure in-domain Recall@100 — MTEB rankings are a starting point, not a verdict.
